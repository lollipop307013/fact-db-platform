## 一、项目背景与目标

### 背景痛点
1. **内容同步无审核**：外部来源（QA/文档库）自动同步的内容直接入库，缺少质量把关
2. **已入库内容改动无审核**：编辑已入库事实后直接生效，无版本追溯和审核机制
3. **重复实体/事实无合并流程**：不同语言分组下可能存在重复实体，无合并入口
4. **冲突检测覆盖不全**：手动添加事实时无冲突/重复检测
5. **多语言添加体验差**：新增实体时切换语言会清空已填写内容
6. **误操作风险**：新建数据时点击空白处会意外关闭编辑内容

### 二期目标（7 项）

| # | 目标 | 优先级 |
|---|---|---|
| 1 | 内容同步审核闭环 | P0 |
| 2 | 已入库内容改动审核（版本对比+回滚） | P0 |
| 3 | 实体/事实合并流程 | P0 |
| 4 | 手动添加事实冲突/重复检测 | P1 |
| 5 | AI 差异识别（审核自动生成差异摘要） | P1 |
| 6 | 新增实体多语言支持（一次性多语言添加） | P2 |
| 7 | 体验优化（防误触 + 冲突对比页优化） | P3 |

## 二、子需求详述

### 子需求 1：内容同步审核功能（P0）

- **目标**：低置信度来源同步的数据必须经审核才能生效
- **来源置信度规则**：
  | 来源类型 | 置信度 | review_status |
  |---|---|---|
  | 手动模板导入 | 高 | ready（直接通过） |
  | Gbot_qa / QA 联动 | 高 | ready |
  | 文档库爬取 | 低 | pending_review（进审核池） |
  | 其他来源 | 低 | pending_review |
- **新增字段**：`source_confidence`（high/low）、`sync_batch_id`（同步批次 ID）
- **审核入口**：新增「审核任务」Tab，任务制管理（按批次/来源聚合），支持批量通过/拒绝
- **审核操作**：通过 → ready；拒绝 → 软删（review_status = rejected）
- **与子2的区别**：子1 覆盖「新增事实」审核（无版本对比）；子2 覆盖「覆盖更新」审核（有版本对比）

### 子需求 2：已入库内容改动审核（P0）

- **目标**：编辑已入库事实后不直接生效，支持版本对比和回滚
- **last_version 机制**：
  - 编辑 ready 事实 → 旧版快照存入 `last_version`，当前内容更新为新版，review_status = pending_review
  - 连续编辑（pending_review 中再编辑）→ last_version 不覆盖，当前内容直接覆盖
  - 审核通过 → review_status = ready，last_version 保留备查
  - 审核拒绝 → 内容回滚为 last_version，review_status 恢复 ready，last_version 清空
- **last_version 快照字段**：fact_text、time_description、title、review_status、`_snapshot_at`
- **AI 差异摘要**：审核抽屉打开时实时 LLM 生成，切换记录打断上一次请求，失败显示兜底文案
- **版本对比高亮**：旧版红色删除线、新版黄色高亮；多语言按当前语言展示，缺失标注「该语言无数据」

### 子需求 3：实体/事实合并功能（P0）

- **目标**：提供人工合并入口，处理重复实体/事实
- **合并流程**：多选记录 → 检测合并条件（至少2条、同语言分组、同游戏、未被软删）→ 合并确认页（选主记录 + 字段映射）→ 执行合并
- **合并执行**：
  - 实体合并：被合并记录软删（deleted=true），其下事实迁移到主记录，关联引用同步更新，操作日志记录 merge
  - 事实合并：主记录保留，被合并软删，last_version 迁移
- **边界**：合并后发现合并错 → 二期不支持撤销，需人工从操作日志恢复
- **二期简化**：直接合并 + 记录，不走审核流程（如需审核三期再做）

### 子需求 4：手动添加事实冲突/重复检测（P1）

- 手动添加事实时，填写完必填字段后点击「检测冲突/重复」
- 复用 `check-contradiction` / `find-duplicates` 接口
- 检测结果在抽屉内展示，确认无冲突后才可提交

### 子需求 5：AI 差异识别能力（P1）

- 审核抽屉打开/内容变更时实时生成一句话差异摘要（LLM）
- 打断逻辑：新请求打断上一次未完成的请求
- 展示：渐变蓝背景卡片

### 子需求 6：新增实体多语言支持（P2）

- 语言选择改为多选（Checkbox 组），抽屉内多语言表单 Tab 切换
- 一次性创建多个语言版本；二期先支持实体

### 子需求 7：体验优化（P3）

- **防误触**：新建/编辑数据点击空白处弹确认框，或 Drawer 禁止 overlay 关闭
- **冲突对比详情页优化**：高亮标记修改点（类 Git diff 红绿对比）

## 三、核心状态与数据模型

### review_status 状态枚举
| 状态 | 说明 | 线上是否召回 |
|---|---|---|
| pending_review | 待审核 | 否 |
| ready | 已审核通过/自动通过 | 是 |
| rejected | 审核拒绝（软删） | 否 |

### 关键接口（待开发）
| 接口 | 用途 |
|---|---|
| POST /api/facts/sync | 来源同步入库（新增 review_status 判定） |
| GET /api/facts?review_status=pending_review | 查询待审核数据 |
| POST /api/facts/:id/review/approve | 单条通过 |
| POST /api/facts/:id/review/reject | 单条拒绝并删除 |
| POST /api/facts/batch_review/approve | 批量通过 |
| POST /api/facts/batch_review/reject | 批量拒绝并删除 |
| POST /api/ai/diff_summary | AI 差异摘要生成 |

## 四、验收要点速览

| 子需求 | 核心验收项 |
|---|---|
| 子1 | 高/低置信度来源入库状态正确；审核任务统计/详情正确；批量通过/拒绝；拒绝软删 |
| 子2 | 编辑 ready 事实触发 pending_review；连续编辑 last_version 不覆盖；通过/拒绝状态流转正确；差异摘要与高亮展示 |
| 子3 | 多选合并入口；合并条件校验；确认页选主记录；合并后事实迁移、软删、操作日志可追溯 |
| 子4 | 手动添加触发冲突/重复检测；确认后才可提交 |
| 子5 | 审核抽屉实时差异摘要；打断与兜底 |
| 子6 | 多语言多选一次性添加 |
| 子7 | 防误触；冲突对比高亮 |
