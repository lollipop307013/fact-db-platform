## 需求 6：问题回复【P1】

### 6.0 业务目标

检测库内知识的覆盖度——业务方输入真实玩家问题，看 AI 用现有事实库能否答上来；答不上来意味着事实库存在盲区。

对应接口：`POST /api/factrag/query`

---

### 6.1 输入区

| 字段（接口参数） | 控件 | 必填 | 说明 |
|---|---|---|---|
| query | Textarea | ✓ | 问题文本 |
| topk | InputNumber | — | 默认 10；返回 top-k 召回结果 |
| similarity_threshold | InputNumber | — | 默认值由后端决定 |
| generate_response | Switch | — | 是否生成 AI 回复（默认开） |
| only_approved | Switch | — | 仅使用 review_status=approved 的内容（默认开） |
| filter_entities_events | Switch | — | LLM 筛选实体/事件 |
| model_name | Select | — | 生成回复的模型 |
| filter_model_name | Select | — | 筛选模型 |
| parent_game_id | （隐藏） | ✓ | 顶部游戏切换 |
| language | （隐藏） | — | 顶部语言切换 |

主按钮：「查询」

---

### 6.2 加载状态

- 提交后显示加载条："正在查询中…"
- 失败时显示具体错误信息

---

### 6.3 结果展示区

后端返回字段：related_facts / related_entities / related_events / entity_relations / expanded_facts / response（可选）

| 区块 | 数据来源 | 展示方式 |
|---|---|---|
| 生成的回复 | response | 文本卡片，仅 generate_response=true 时返回 |
| 参考事实（按相似度排序） | related_facts | 列表，每条显示 fact_text + similarity 分数 + 来源 |
| 参考实体 | related_entities | 实体卡片（entity_name + tags + description） |
| 参考事件 | related_events | 事件卡片（event_name + 时间） |
| 参考实体关系 | entity_relations | 实体间关系展示（图谱方式或列表） |
| 扩展事实 | expanded_facts | 通过实体/事件关联扩展出的事实 |
| 匹配明细 | related_facts[*].similarity 等 | 直观展示此次回答命中的意图、召回的图谱实体、引用的事实 |

---

### 6.4 业务规则

- **多游戏隔离**：query 时必须带 parent_game_id；切游戏后历史结果清空
- **多语言支持**：language 从顶部全局切换继承；返回结果按当前语言展示，缺失则 fallback 到 zh
- **空结果**：无召回时给空状态提示"事实库中没有找到相关内容"
- **业务用途**：业务方可基于"答不上来"的问题反推事实库需要补充的盲区，导出 query 列表可作为后续提取的输入

---

### 6.5 与其它模块的关联

- 数据来源：事实库 review_status=approved 且 upload_status=done（已同步到 RAG/Bot）的事实、实体库 / 事件库 review_status=approved 的条目
- 输出：业务方可基于"答不上来"的问题反推事实库需要补充的盲区
