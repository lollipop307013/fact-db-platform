> **下次需要补充的调研动作**（待服务恢复后执行）：
> 1. 实体 Tab：新建一个实体填全字段、查看返回结构是否有 aliases；点击编辑看字段集
> 2. 事件 Tab：新建事件填时间字段、看树状视图是否真支持父子层级
> 3. 事实 Tab：新建事实看 status/source/relatedEntities 字段；尝试关键字搜索
> 4. 提取 Tab：粘文本调一次提取，看返回结构、是否有任何审核/落库环节
> 5. 问答 Tab：问一次，看召回结果如何分组与展示
> 6. 错误检测 Tab：检测一次，看结果详情结构
> 7. 全程开 network 监听记录每个请求/响应字段

## 一、整体结论

线上版本是**接口可跑通的最小骨架**——5 个 Tab 都建出来了，单条 CRUD 通了，但**几乎所有产品规则、批量能力、审核流转、状态字段都没落地**。

| 维度 | 线上 | PRD 期望 | 差距 |
|---|---|---|---|
| 模块覆盖 | 5/5 ✅ | 5/5 | 0 |
| 单条 CRUD | 5/5 ✅ | 5/5 | 0 |
| 批量能力 | 0 | 多模块都需要 | 🔴 大 |
| 审核流转 | ❌ | 提取审核工作台核心 | 🔴 大 |
| 状态/字段 | 部分缺失 | 7 个子需求全部需要 | 🟡 中 |
| 文件解析/导入 | ❌ | 子2 核心 | 🔴 大 |
| 操作记录/状态机 | ❌ | 子5 核心 | 🟡 中 |

**整体进度**：线上≈完成 PRD 的 **15%**，主要是基础 CRUD；产品价值最高的"审核流转+批量入库+冲突合并"全部未启动。

## 四、建议优先级（评审用）

按"产品价值 × 当前完成度"排序，给开发明确推进顺序：

### 🔴 P0 立刻推（核心闭环）

1. **子1 提取结果审核工作台**：从"提取调用"延伸到"批次列表 + 单条审核 + 入库"完整闭环，是产品价值最高的部分
2. **子4 事实库状态字段**：这是入库后的下游链路，没有它子1 入库后无去处
3. **子5 操作记录与状态机**：入库/上线/下线的留痕能力，质量与回溯都依赖它

### 🟡 P1 紧跟（批量与协作）

4. **子0 批量导入（实体/事件/事实）**：开发能复用同一个 ImportDialog 组件，工程量集中
5. **子2 文件解析 + 多源导入**：提取 Tab 的文件上传、Confluence/PDF 解析

### 🟢 P2 后置（增强 / 优化）

6. **子3 字段完整性**（aliases、父子事件、关联检查）
7. **子6/子7 验证现有实现，按需补强**
8. **子0 批量删除、合并**
