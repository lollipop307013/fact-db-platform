## 需求 2：多源批量导入【P0】

### 2.0 业务目标

支持业务方将项目组提供的结构化文件直接导入系统，自动解析为候选事实进入审核流（或直接入库），省去手工粘贴。

**首期范围**：

| 项 | 首期 | 后续 |
|---|---|---|
| 文件格式 | **仅 CSV** | PDF / Word / Excel / TXT 待 Skill 自动识别能力具备后做 |
| 解析方 | **后端解析** | - |
| 模板数量 | **4 份独立模板**：抽取 1 份 + 实体/事件/事实管理各 1 份 | - |
| 是否走抽取 | **由入口决定**，无需靠某列判断 | - |

> UI 层不出现"白皮书"概念（业务术语对普通用户太专属）。文件入口统一文案为"文件导入"或"批量导入"。

> ⚠️ v3.1 关键修订：v3.0 的"管理 Tab 与 ExtractTab 共用一份模板靠 related_info 触发抽取"已废弃。实际为 **4 份独立模板**，由入口决定走抽取还是直入。

### 2.2 四份模板字段定义

> ⚠️ 模板列名采用**中文**（用户友好），前端读取时映射到后端 snake_case 字段。下表"列名"为模板真实列头。

#### 2.2.1 事实抽取批次模板（CSV抽取）

> 用途：ExtractTab 文件导入；走 LLM 抽取，每行的「知识文本」喂给模型抽出多条事实+关联实体/事件，进审核区批次卡片。

| 列名 | 必填 | 后端字段 | 说明 |
|---|---|---|---|
| 标题 | - | title | 该行/该批次的标题，可选 |
| 其它上下文 | - | context | 抽取时给 LLM 的额外背景信息，提升准确度 |
| 知识文本 | ✅ | content | 待抽取的原文（LLM 输入主体）|
| 分类ID | - | category_id | 抽取出的事实统一归属此分类 |
| 来源类型 | - | source_type | 自定义来源类型，如 `wiki` `manual` |
| 来源 | - | source | 来源 URL 或来源说明 |
| 扩展信息 | - | extra | JSON 字符串，业务方自定义透传字段 |

**示例**：

```csv
标题,其它上下文,知识文本,分类ID,来源类型,来源,扩展信息
张三角色介绍,游戏背景：东方玄幻,张三是一名修真者…冷却 60 秒。,3001,wiki,https://wiki.example.com/zhangsan,
春节活动公告,2026 年 2 月运营活动,春节活动期间…活动时间 2026-02-10 至 2026-02-20。,3002,manual,运营公告,"{""campaign_id"":""SPRING_2026""}"
```

### 2.3 上传流程（异步占位卡片）

无论走抽取还是直入，整个 CSV 文件**始终异步**处理：

```
用户选择 CSV
  ↓ 前端上传文件（multipart/form-data）
  ↓ 后端返回 task_id + status=pending
  ↓ 前端立即在审核区/管理 Tab 顶部生成占位卡片
  ↓ 前端按 §子1 §1.16 轮询策略调状态接口
  ↓ 后端解析 CSV → 逐行调对应接口（抽取 OR 创建）
  ↓ 完成 → 前端拉结果展示
```

**ExtractTab 入口**的占位卡片：

- 整个 CSV 文件 = 1 个批次（5/13 会议 w5 决策）
- 占位卡片视觉/状态机/轮询/并发限制/失败兜底，复用 [子1 §1.16](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126280)
- success 时占位卡片就地转为正式批次卡片，所有抽取出的事实合并展示在该批次下
- **批次卡片"查看原文"**：CSV 类型显示**文件名 + 超链 + 下载入口**（不展示文本原文）

**管理 Tab 入口**的占位卡片：

- 位置：列表顶部置顶展示（与审核区独立）
- 视觉简化版（无批次概念，只显示文件名 + N/M 行进度）
- success 时弹 toast「已成功导入 N 条，失败 M 条；已刷新列表」并消失

#### 2.3.1 失败行处理

后端解析或入库过程中**部分行失败**时（例：实体名重复、必填字段缺失）：

- 整体 status=success（不阻断成功行）
- 卡片头部加 `⚠ N 行异常` Tag
- 点击 Tag 展开异常行原文 + 错误原因（CSV 第几行 / 缺哪个字段 / 失败原因）
- 用户可下载「失败行 CSV」修订后重新上传

### 2.4 业务规则

- 文件大小限制：≤ 5MB（首期）
- 编码：UTF-8 with BOM
- 列名匹配：**严格按模板列名**（中文），列顺序可乱，多余列忽略
- 必填字段缺失 → 该行计入失败行，不阻断成功行
- 单次上传行数 ≤ 1000 行
- 模板下载入口：每个批量导入 / 文件导入入口都提供「下载模板」按钮
- parent_game_id：模板中**不暴露**，前端在上传时按当前顶部游戏切换值自动注入
- source_type：抽取批次的 source_type 由后端自动填为 `extract_csv`，事实管理直入的事实保留用户填的来源类型
