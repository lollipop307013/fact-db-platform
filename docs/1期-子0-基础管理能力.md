## 需求 0：实体 / 事件 / 事实管理基础能力【P0】

### 0.0 业务目标

实体管理（Entity Tab）、事件管理（Event Tab）、事实管理（Fact Tab）作为事实库的基础数据管理界面，提供标准的增删改查与列表筛选能力，是审核工作台之外最常用的日常操作入口。

本子需求统一描述这三个 Tab 的**通用基础能力范围**，避免在子1～子7 中分散描述、首期边界不清。

> 字段命名、状态取值、多语言、多游戏隔离均以[附录 § 二、字段命名与状态规范](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126457)为准。

### 0.2 首期范围（明确做 / 不做）

#### ✅ 首期做

- 三个 Tab 的标准 CRUD：列表、单条新建、单条编辑、单条删除（带二次确认）
- 列表筛选与排序：按关键字、tag_id、review_status、parent_game_id、language、source_type 等组合查询
- 三态统计栏（顶部）：实体/事件/事实各自的 pending/approved/deleted 数量
- 单条审核状态变更（按状态机校验，详见[子5](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126267)）
- 批量审核状态变更（多选 → 批量改 review_status）
- 事实 upload_status 同步状态只读展示 + 异常筛选（详见 [子4](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126273)）
- 批量导入 CSV：实体 / 事件 / 事实三模块各自支持
- 事实导出 Excel：按当前筛选条件；勾选"多语言"导出 6 语种列
- 实体管理：标签树状视图、Tag Tab 切换
- 事实管理：分类树形面板（左侧）
- 顶部全局**游戏切换下拉**（来自 `/api/games`），切换游戏时整个工作台数据切换
- 顶部全局**语言切换**，影响列表展示的字段语言

#### ⚠️ 首期补做（缺口，高优先级）

| 缺口 | 模块 | 涉及接口 |
|---|---|---|
| 批量删除按钮 | 实体 / 事件 | entities/batch-delete、events/batch-delete |
| 批量操作栏 | 事件管理 | events/batch-update-review-status |
| 顶部三态统计 | 实体 / 事件 | entities/stats、events/stats |
| 错误检测「批量更新入库」 | 错误表述检测 | facts/batch-update-corrected（详见 [子7](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126415)） |
| 多游戏切换全局贯穿 | 全模块 | 所有接口 + parent_game_id |
| 多语言字段录入与展示 | 全模块 | 字段 _en / _ar 等多语言后缀 |

#### ❌ 首期不做（已有接口但视使用频率延后）

| 不做项 | 推迟原因 | 划入 |
|---|---|---|
| 批量字段编辑（如批量改标签） | 实际场景中用单条编辑可覆盖多数情况 | 2 期视使用频率 |
| 实体合并 / 事件合并 | 需独立合并向导，工程量较大 | 2 期 |
| 批量关联实体 / 事件（Fact） | 当前事实编辑 Dialog 内逐条关联可满足 | 2 期 |
| 一键判断+修复（错误表述） | 分步操作已覆盖，一键模式安全性需评估 | 2 期 |
| 矛盾召回精确接口（recall-potential-contradictions、coarse-filter） | 当前 mock 数据可演示，联调时接入即可 | 当前迭代联调 |
| 单对矛盾核验（check-contradiction-pair） | 用户反馈很少需要 | 不在范围 |
| 事实归并（merge-candidates / batch-merge-duplicates） | 重复治理首期靠提取阶段的"重复检测"提示 | 不在范围 |
| 单条事实追加关联（POST /api/facts/{id}/entities/{id}） | 编辑表单内修改 entity_ids[] 已能满足 | 不需要 |

#### ❌ 后端尚未提供（影响首期能力）

| 缺失接口 | 影响 | 处理方案 |
|---|---|---|
| facts/batch-delete | 事实无法批量删除 | 首期只允许逐条删除；如需批量需后端补接口 |
| events/recall（语义召回） | 事件选择器无语义召回能力 | 首期事件选择器走关键字 + 列表挑选 |
| 操作日志专属接口 | 操作记录的实现路径未定 | 待和后端确认（详见 [子5](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126267)） |

### 0.3 通用交互规则

- **危险操作二次确认**：删除、批量删除、合并必须弹 Dialog 二次确认；含已上线 / 已通过条目时显著红字警告
- **批量操作多选**：列表行首 Checkbox + 表头全选；选中后顶部出现操作栏（已选 N 条 + 操作按钮）
- **状态变更校验**：按状态机规则校验合法迁移，不允许的迁移弹 toast 拦截（详见 [子5 状态机](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126267)）
- **操作留痕**：所有增删改、状态变更、批量操作均写入操作记录
- **空状态文案**：列表为空 / 筛选无结果 / 关联模块为空，使用统一文案（详见[附录 § 关键空状态](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126457)）
- **多游戏切换**：顶部全局下拉，切换后整个工作台刷新；未选游戏时给出空状态提示
- **多语言**：列表/编辑/导出全支持，详见 [子3 § 3.5](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126276)

### 0.5 验收要点

- 三个 Tab 列表筛选条件可组合查询，分页与排序无错乱
- 单条 CRUD 完整闭环，编辑保存后列表实时刷新
- 三态统计栏数据与列表筛选结果一致
- 批量状态变更对不合法迁移的条目自动跳过并 toast 反馈"已对 M 个执行，N 个已跳过"
- 删除/批量删除/批量状态变更均写入操作记录，操作人/时间/动作可追溯
- 缺口项（批量删除、事件批量操作栏、错误检测批量入库、统计栏、多游戏、多语言）首期上线前完成补做
- 多游戏切换后所有接口请求带正确 parent_game_id；多语言切换后列表字段语言切换正确
