提取事实 · 操作指引

按流程走 6 步，从一段文本到入库事实；每步附带业务规则

1
粘贴文本 或 上传 CSV 操作

左侧输入区，两种方式进入提取：

📝 粘贴文本
白皮书 / 公告 / 攻略原文直接贴进文本框
最少 12 行高度，自动展开
📎 上传 CSV
用"事实抽取批次模板"填好的 .csv 文件
走后端解析，每行"知识文本"列喂给 LLM
操作
  • 选择输入方式（文本 / 文件）
  • 选择提取模式：单段提取（整段 = 1 条事实） / 多段提取（AI 自动拆分多条），每个选项带 ⓘ 解释气泡
  • 选择模型（下拉，后端配置可用列表）
  • 点「提取事实」→ 按钮进 loading 态
规则
  • 文本为空 → toast「请输入文本内容」，不调接口
  • 提取完成 → toast「提取完成（{batchId}），生成 N 条事实」，自动清空文本框便于继续
  • Loading 文案：按钮下方「提取中，结果将出现在右侧…」，完成自动消失
  • CSV 模板列名：标题 / 其它上下文 / 知识文本（必填）/ 分类ID / 来源类型 / 来源 / 扩展信息
2
等 AI 抽取 → 看批次卡片 结果

提取完成后右侧审核区出现批次卡片，按时间倒序排列。

批次头信息
  • 批次编号 Tag（点击复制到剪贴板）
  • 批次标题（来源文本前 40 字）
  • 副信息：提取时间 · 提取人（自己的标"（我）"品牌色高亮）· 模型 · 模式 · 共 N 条
  • 状态徽章：待审核 N / 已通过 N / 已拒绝 N
  • 2px 审核进度条（蓝色填充已审占比，全部审完变绿）
规则
  • 提取结果团队级共享可见，非仅自己
  • 文本粘贴批次「查看原文」展示原始文本；CSV 批次展示文件名 + 超链 + 下载入口
  • 批次可折叠/展开，进度条折叠时也可见
  • 已归档批次不显示进度条
3
逐条审核候选事实 核心

每条事实一行卡片，三栏：事实内容 | 关联信息 | 操作区

看什么
  • 事实内容是否准确
  • 冲突 Tag（红）→ 点开对比 Dialog
  • 重复 Tag（黄）→ 看相似度+片段
检查什么
  • 关联实体 / 事件对不对
  • 黄色「建议新增」实体/事件 → keep 还是 discard
  • 有效时间（开始~结束 + 时间描述）
操作
  • 没问题 → 「通过」✅
  • 要改 → 「编辑」改完再通过 ✏️
  • 不对 → 「拒绝」❌
当前状态编辑通过拒绝撤回删除
待审核 ✓✓✓—✓
已通过 ✓（仅改内容）——✓→待审核✗
已拒绝 ✗——✓→待审核✓
规则
  • 已通过/已拒绝不可互相横跳，只能撤回到待审核再重新审
  • 已通过可编辑但仅改内容，不改状态
  • 已拒绝不能编辑，需先撤回
  • 日志按钮带条数 Tooltip："查看操作记录（N 条）"
  • 已有实体 = 灰色 Tag 可关闭（移除关联）；建议新增实体 = 黄色 Tag 点击切换 keep/discard
4
编辑抽屉（80% 屏宽） 编辑

点行内「编辑」→ 右侧抽屉，左右双栏（1.2 : 1），各自独立滚动。

左栏 · 事实主体
  • 多语言切换：顶部 6 语种按钮（zh/en/ar/tr/ru/zh-hk），仅影响事实内容、时间描述、标题 3 个字段
  • 事实内容（fact_text）：必填，Textarea，实时冲突/重复校验
  • 时效：开始时间 / 结束时间 + 时间描述
  • 关联实体：搜索下拉添加 + 新发现实体卡片（名称/描述/标签，保留时显示绿色 ID Tag）
  • 关联事件：同上 + 新发现事件卡片（名称/类型/时间/描述/标签）
右栏 · 元数据（4 组）
  • A. 基础信息：标题（多语言）/ 分类 / 审核优先级
  • B. 来源溯源：来源类型（只读）/ 来源 / 来源URL / 来源内容
  • C. 矛盾与重复：矛盾原因 / 矛盾事实ID / 重复事实ID
  • D. 扩展：extra（自由 JSON 字符串）
关键约束
  • 多语言切换只影响 3 个字段：fact_text / time_description / title，其它字段语言无关
  • 非当前语种按钮，若已填充过则右侧加绿点提示
  • 来源类型 source_type 不可编辑（保留系统提取来源）
  • extra 非空时必须是合法 JSON，否则红框 + 保存被拦截
  • 冲突/重复实时校验仅在 zh 模式下展示，切其他语种自动隐藏
  • 已拒绝状态不允许打开编辑抽屉
📖 保存逻辑（点击展开）
保存 5 步
  • ① 校验扩展 JSON：失败时 toast 错误并 return
  • ② 基于最新 content 重新查冲突
  • ③ 校验结果（conflict/duplicate）写回审核区条目
  • ④ 自动生成编辑摘要写入操作日志，如「修改了：事实内容、标题、已解除与 [ID:42010] 的重复」
  • ⑤ Toast「已保存」；若有冲突/重复解除，额外 toast
5
整批操作 & 批量导出 快捷
批次头按钮
  • 「整批通过」→ 批次内全部待审核条目一键通过
  • 「整批拒绝」→ 批次内全部待审核条目一键拒绝
  • 已审过部分时按钮文案变「剩余全部通过 / 剩余全部拒绝」
  • 按钮 minWidth 96 防文案切换时位移
批量导出 CSV 规则
  • 勾选事实 → 点「导出 CSV」
  • 必须选中整个批次的全部事实，否则 toast「只允许导出整个批次的数据」
  • 支持选多个批次，合并成一份 CSV
  • 导出范围：待审核 + 已通过 + 已拒绝 三态全导出
  • 不附带审核人 / 审核时间 / 审核备注
  • 不加 batch_id 列
  • 列名用中文表头（对齐事实导入模板）
  • 多语言列首期不导出

6
审核完毕 → 入库归档 完成

批次内无待审核 → 进度条变绿 → 可入库。

入库方式
  • 单批次：批次头的通过/拒绝按钮自动变成绿色「入库 / 归档批次」
  • 多批次：顶部「入库 / 归档已完全审核批次」一键入库所有已完成批次
入库后
  • 已通过 → 进入事实库（管理 Tab 可见），review_status=approved
  • 已拒绝 → 留痕（review_status=deleted），供训练用
  • 批次归档（archiveReason=committed），审核区不再显示
同步状态（upload_status）
  • 入库后 upload_status 由后端自动维护，前端无手动操作
  • 四态流转：pending（待上传）→ need_update（待更新）→ done（已上传）→ failed（上传失败，后端自动重试）
  • 前端仅做展示 + 异常筛选（上传失败的事实可筛出来关注）

🗑 删除批次

批次头右侧 × 按钮 → 二次确认。
含已通过未入库条目时弹窗红字警告，按钮文案变「仍要删除」。

🔄 撤回审核

已通过 / 已拒绝 → 点「撤回」→ 回到待审核。
审核区是缓冲池，允许反悔。但不可互相横跳（已通过不能直接变已拒绝）。

👁 只看自己的

顶部「全部 / 只看自己的」切换。
提取结果团队共享，自己的标「（我）」品牌色。切换后统计和入库按钮均按筛选后数据计算。

📂 左栏收起

中间分割线悬浮小条 → 点击收起左侧输入区，右侧审核区占满全宽。
再点恢复。提取完了专注审核时用。
