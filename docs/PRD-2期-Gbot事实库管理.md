## 一、项目背景与目标

### 1. 2 期出发点

首期解决了"能用"的问题，2 期重点解决四件事：
- **多语言**：海外业务团队需要把事实库扩展到英语 / 阿拉伯语 / 土耳其语 / 俄语等
- **协作冲突**：多人同时编辑时不能互相覆盖
- **外部审核**：批次内容可发给外部审核者（外包标注、运营），凭批次 ID 协作，隐藏原始文档保护信息安全
- **运营治理**：错误表述检测要能形成"发现 → 修复 → 落库"的闭环

### 2. 2 期目标

| # | 目标 | 衡量 |
|---|---|---|
| 1 | 多语言事实管理 | 支持单条事实多语言版本；切换语言时事实库内容自动切换 |
| 2 | 协作版本控制 | 同时编辑同一记录时，后保存者收到冲突提示，可选择"我的"/"对方"/"合并" |
| 3 | 外部审核链路 | 内部审核者可生成带签名的外部审核链接；外部审核者可在隔离页面提交反馈；内部可查看反馈并采纳/忽略 |
| 4 | 错误表述自动修复闭环 | 检测到错误的事实可一键发起修复任务，修复结果走审核流落库 |
| 5 | 操作记录全局检索 | 跨记录、跨人员、跨时间的日志检索与导出 |

## 需求 1：多语言事实管理【P0】

### 1.0 业务目标

让一条事实支持多语言版本（中文 / English / العربية / Türkçe / Русский / 粤语），并在事实库 / 实体 / 事件三处统一接入。

### 1.1 数据模型扩展

字段从单值改为 map：

```ts
interface FactMultilingual {
  content: { [lang: string]: string };   // 而不是单 string
  title:   { [lang: string]: string };
  timeDesc: { [lang: string]: string };
  // ...
}
```

### 1.2 编辑表单的多语言 Tab

- 编辑抽屉 / Dialog 顶部加 Tabs：中文 / English / 其他语言
- 每个 Tab 独立编辑同字段的不同语言版本
- 必填语言：仅中文；其他语言可选填，未填时回退到中文展示

### 1.3 列表视图语言切换

- 工具栏顶部"语言切换器"作用范围扩大：影响表格内 content / title 的实际展示
- 缺失语言版本的行：用浅灰色 + 文案"（暂无 X 语言版本）"

### 1.4 多语言别名维护

实体 / 事件支持多语言别名（每行一个）。

### 1.5 与其它模块的关联

- 事实管理：表头默认按当前语言展示
- 提取审核：暂不支持多语言提取（保持中文为主）；入库时事实进入"中文版本"，其他语言在事实库内补充
- 问答：QA 模块按当前语言检索

## 需求 2：协作版本控制【P1】

### 2.0 业务目标

防止多人同时编辑同一条事实时互相覆盖。

### 2.1 编辑态锁

编辑抽屉打开时，向后端注册一个"编辑中"标记（带过期时间，30 分钟）。其他人此时打开同条记录会看到提示：「xxx 正在编辑，预计 X 分钟后释放」，仍可只读查看。

### 2.2 保存时的版本检测

- 抽屉打开时记录"基线版本号"
- 保存时后端比对当前数据库版本号
- 不一致 → 弹"版本冲突 Dialog"：左侧"我的修改"，右侧"他人已保存的版本"，按字段高亮差异
- 用户选择：保留我的 / 保留对方 / 字段级合并

### 2.3 操作日志补充

操作日志的 detail 字段补充冲突解决记录：「与 xxx 的修改产生冲突，最终采用：我的版本（保留 content / events，使用对方的 keywords）」

## 需求 3：外部审核链路【P0】

### 3.0 业务目标

让批次审核可以分发给外部协作者（外包标注、运营、海外团队），凭批次 ID 协作；外部页面隐藏原始文档与内部元信息，保护信息安全。

### 3.1 批次 ID 已就绪（首期完成）

- 批次 ID 已在首期规范化为 `BATCH-{YYYYMMDD}-{seq}`（详见首期 PRD §四 3 ID 与命名规范）
- 卡片头展示 + 一键复制 已就绪
- 2 期在此基础上扩展外部链路

### 3.2 生成外部审核链接

- 批次卡片头新增「分享审核」按钮，仅对内部审核者可见
- 点击弹生成对话框：
  - 接收人邮箱 / 企微账号（可多选，邮件 / 企微推送通知）
  - 链接有效期：24 小时 / 7 天 / 30 天 / 自定义
  - 权限范围：可审核（提交意见）/ 仅查看
  - 是否允许导出（默认关）
- 提交后返回带签名的 URL：`/external-review/{batchId}?token={签名 token}`
- token 含批次 ID、过期时间、权限、签发人；服务端校验
- 内部审核者可在批次详情查看「已分享」记录（对谁、何时、状态：未访问/已访问/已审核完成）

### 3.3 外部审核页面（独立路由）

外部页面与内部完全隔离，UI 简化：

**看得到**：
- 批次 ID（页面顶部，明显位置）
- 批次内候选事实条目列表（事实内容 + 关联实体 + 关联事件）
- 冲突 / 重复提示（仅展示"该事实可能与库内已有事实冲突 / 重复"，不展示对方 ID 与对比详情）
- 自己提交过的反馈

**看不到**：
- 原始来源文档（PDF / Word / 表格）与原文文本
- 提取人 / 模型 / 内部元信息
- 库内其它事实详情

**能做**：
- 对每条事实选择：通过 / 拒绝 / **标注疑问**（外部审核者不直接拍板，标注疑问 = 给意见）
- 拒绝 / 标注疑问需填写理由
- 提交反馈后页面进入只读态，不可再修改

### 3.4 内部反馈回填

- 批次卡片头展示外部反馈摘要：`外部审核：通过 N · 拒绝 N · 疑问 N`
- 单条事实行展示外部反馈 Tag：`外部：通过 / 拒绝 / 疑问`
- 内部审核者点击 Tag 看完整反馈（理由 + 提交人 + 时间）
- 内部最终审核保留决策权：可"采纳外部意见"或"忽略外部意见"
- 外部反馈写入操作日志：`收到外部审核：xxx 标注「疑问」-- 该事实表述与游戏内实际机制不符`

### 3.5 安全规则

- token 过期后访问返回固定提示页"该审核链接已失效，请联系内部审核者"
- 外部审核者无登录态，仅凭 token；token 不可重复使用提交（提交后立即失效）
- 同一批次的不同 token 各自独立、各自记录
- 链接可被内部审核者主动撤销

### 3.6 与其它模块的关联

- 批次 ID 来自首期
- 操作日志：外部反馈作为事件记入批次的 logs[]
- 安全：与平台统一的 token / 签名机制（具体由后端实现）

## 需求 4：错误表述检测自动修复闭环【P0】

### 4.0 业务目标

把首期"检测到错误 → 给建议"，扩展为"检测 → 修复 → 审核 → 落库"。

### 4.1 检测增强

- 沿用首期检测能力
- 输出每条错误的"修复建议事实"（自动生成）

### 4.2 批量发起修复任务

- 检测结果列表勾选 N 条 → 点"批量发起修复"
- 后台创建修复任务，把修复后的事实推入"提取结果审核"区（与首期主链路融合）
- 在审核区中标记 batchLabel = `[修复] xxx 错误表述检测任务`

### 4.3 修复任务监控

- 错误表述检测页加"我的修复任务"列表
- 列：任务 ID / 时间 / 状态（处理中 / 已入审核区 / 已审核入库 / 已废弃）
- 链接：跳转到对应审核区批次

## 需求 5：操作记录全局检索【P1】

### 5.0 业务目标

把分散在各记录的操作日志聚合，支持运营运维检索。

### 5.1 操作记录中心页

新增一级菜单（或放在"系统设置"下）：操作记录中心。

筛选维度：
- 时间范围
- 操作人
- 模块（实体 / 事件 / 事实 / 审核区）
- 动作类型（创建 / 编辑 / 状态变更 / 回退 等）
- 关键词（detail 文本搜索）

### 5.2 导出

- CSV 导出筛选结果
- 包含：模块 / 记录 ID / 记录标题 / 操作人 / 时间 / 动作 / 详情

## 需求 6：树状视图 / 分类与游戏实体分离【P2】

### 6.0 业务目标

实体管理目前是一张大表，分类与游戏实体混杂。2 期分离两者，让维护更清晰。

### 6.1 候选方案（待评审）

- **方案 A**：实体表加 kind 字段（category / game），列表加切换 Tab
- **方案 B**：分类独立成单独的"分类管理"页，游戏实体引用分类作为外键

倾向 A。

### 6.2 树状视图增强

如果首期的树状视图实际使用率高，2 期增加：
- 节点间拖拽迁移
- 父子分类批量重命名
- 分类合并（把 A 分类下的所有实体迁到 B 分类）

### 6.3 网状视图

如果业务有强需求，2 期评估实现。本期保持占位，**默认不做**。

## 需求 7：提取能力增强【P2】

### 7.1 批次搜索 / 跨日期筛选

- 审核区顶部加搜索框：搜批次 batchLabel / 提取人 / 模型
- 加日期范围选择器

### 7.2 多文件批量解析

首期单文件解析，2 期支持一次上传 N 个文件，逐一解析进同一批次或多批次。

### 7.3 模板式提取

针对结构化文件（Excel），允许用户配置"列名 → 字段映射"，提高提取准确率。
