## 一、项目背景与目标

### 1. 业务背景

- **痛点**：基于大模型的游戏客服与助手存在严重幻觉，回答事实精度无法保证。
- **核心对策**：将松散的业务长文档，通过机器预处理 + 大模型抽取，转化为结构化的"事实（Fact）"，并挂载在游戏的"实体（Entity）"和"事件（Event）"图谱节点上，以高结构化的形式反哺 AI 问答。
- **核心价值**：把"AI 提取 + 人工审核"打造为生产可用的核心生产链路，让业务方可以低门槛、可追溯地批量产出图谱知识。

### 2. 首期目标

| # | 目标 | 衡量 |
|---|---|---|
| 1 | 提取审核流程闭环 | 业务方可在工作台完成 AI 提取 → 逐条审核 → 入库的全流程，平均单条审核耗时 ≤ 30s |
| 2 | 多源批量入库 | 文本粘贴、PDF / Word / Excel / CSV 文件均可作为入口产出候选事实 |
| 3 | 数据治理可追溯 | 实体 / 事件 / 事实每一次状态变更与字段编辑均有完整记录 |
| 4 | 异常可见 | 向量同步失败、冲突 / 重复事实在列表中可一眼看到并支持快速处理 |
| 5 | 多人协作 | 提取结果共享可见、按提取人筛选；状态机校验防止误操作 |

## 需求 1：提取结果审核工作台【P0】

### 1.0 业务目标

把 AI 提取的事实组织为分批次、可对比、可追溯、状态明确的工作流，是事实库的主进货口。

**整体页面结构**：

左右两栏：
- **左侧（占比 30%）**：提取输入区（可收起）
- **右侧（占比 70%）**：提取结果审核区，按批次组织

**左侧收起/展开**：
- 左右两栏之间有一根细分割线，中间悬浮一个小矩形条（浅灰色，14×48px）
- 点击小条 → 左侧输入区折叠，右侧审核区占满全宽
- 再次点击 → 恢复原始比例
- 收起状态下分割线渐隐；展开时恢复
- 适用场景：提取完成后专注审核，无需再输入文本

---

### 1.1 提取输入区

| 字段 / 控件 | 说明 |
|---|---|
| 输入方式切换 | 文本粘贴 / 文件上传（详见需求 2） |
| 文本输入框 | 支持多行粘贴，最少 12 行高度，自动展开 |
| 提取模式 | 单段提取（整段 = 1 条事实） / 多段提取（自动拆为多条），每个选项带 ⓘ 解释气泡 |
| 模型选择 | 下拉选择 LLM，由后端配置可用模型列表 |
| 提取按钮 | 点击进入加载态 |
| Loading 文案 | 紧贴按钮下方"提取中，结果将出现在右侧…"，加载完成自动消失 |

**业务规则**：
- 文本为空 → 报错 toast"请输入文本内容"
- 提取完成 → toast"提取完成（{batchId}），生成 N 条事实"
- 提取后清空文本框，便于继续粘贴下一段

### 1.2 审核区顶部

| 元素 | 说明 |
|---|---|
| 标题 | "提取结果审核" |
| ⓘ 帮助图标 | hover 弹层展示完整使用说明（5 步流程 + Tag 含义） |
| 统计 | 共 N 条 · 待审核 N · 已审核 N |
| 范围筛选 | 全部 / 只看自己的（默认"全部"） |
| 已审核全部入库 | 按当前筛选范围把所有"已审核"条目入事实库 |

**业务规则**：
- 提取结果团队级共享可见
- 筛选范围切到"只看自己的"时，统计、入库按钮均按筛选后的数据计算

**帮助图标弹层文案**（首期固定文案）：

```
使用说明
AI 提取的事实先进入此处暂存，审核通过后才会入库。所有人共享可见。

使用步骤：
1. 左侧粘贴文本，选择提取模式后点「提取事实」
2. 右侧按批次查看提取结果，逐条核对：
   • 事实内容是否准确
   • 关联实体 / 新发现实体 / 关联事件 / 新发现事件
   • 冲突 / 重复事实提示（点击 Tag 可查看对比）
3. 必要时点「编辑」修改内容（编辑保存后会重新校验冲突）
4. 逐条「通过」/「拒绝」，或整批通过 / 拒绝
5. 已审核条目通过顶部「已审核全部入库」批量入库（直接以「已审核」状态进入事实库，相关批次自动归档）
```

### 1.3 批次卡片

每次提取生成一个批次，按时间倒序展示。

**批次字段**：

| 字段 | 说明 |
|---|---|
| batchId | 批次业务编号，规则详见 §四 3 ID 与命名规范 |
| batchLabel | 自动取来源文本前 40 字 |
| extractedAt | 提取时间 |
| extractor | 提取人（用于追溯 + 筛选） |
| model | 使用的模型 |
| mode | 单段提取 / 多段提取 / 文件解析 |
| facts | 该批次的候选事实数组 |

**批次头展示**：
- 批次编号 Tag（独立显著展示，点击一键复制到剪贴板）
- 批次标题（来源文本前 40 字）
- 副信息：提取时间 · 提取人（自己提取的标"（我）"，品牌色高亮）· 模型 · 模式 · 共 N 条
- 状态徽章：待审核 N / 已审核 N / 已拒绝 N（按数量出现）

**批次头交互**：
- 折叠 / 展开 该批次
- **查看原文 / 查看来源内容**（折叠面板）：
  - 文本粘贴批次：展示用户粘贴的原始文本
  - 文件导入批次（mode=文件解析）：展示来源文件名 + 被提取的各片段位置标记和内容；按钮文案改为「查看来源内容」
- 整批通过：把批次内所有"待审核"条目改为"已审核"（已标注的不受影响，取差集）
- 整批拒绝：把批次内所有"待审核"条目改为"已拒绝"（弹确认）
- 删除批次：整批移除（弹确认）

### 1.4 单条事实行（FactRow）

每个批次内的事实以行卡片展示，结构为三栏：

```
┌──┬─────────────────────┬──────────────────┬──────────┐
│序│ 事实内容（可宽展示）  │ 实体匹配 / 事件匹配 │ 操作区    │
│号│ ⚠ 冲突事实：[ID:xxx] │ + 时间信息         │ 状态徽章  │
│  │ ≈ 重复事实：[ID:xxx] │                  │ 编辑/通过 │
│  │                     │                  │ 拒绝/撤回 │
│  │                     │                  │ 删除/日志 │
└──┴─────────────────────┴──────────────────┴──────────┘
```

#### 1.4.1 左侧 · 事实内容区

- 完整展示事实文本
- **冲突 Tag**：`⚠ 冲突事实：[ID:xxx]`（红色），hover Tooltip 看冲突原因；点击弹"对比 Dialog"
- **重复 Tag**：`≈ 重复事实：[ID:xxx]`（黄色），hover 看相似度+片段；点击弹"对比 Dialog"
- 同时存在冲突与重复时，两个 Tag 并列展示

#### 1.4.2 中间 · 关联信息区

**实体匹配**：
- 已有实体：灰色 Tag，可关闭（关闭即移除关联）
- 建议新增实体：黄色 Tag，文案 `建议新增：xxx · N 标签`，hover 看描述+标签预览，点击 Tag 切换 keep / discard 状态

**事件匹配**：
- 已有事件：灰色 Tag，可关闭
- 建议新增事件：黄色卡片，含名称 / 类型 / 时间 / 描述；右上"丢弃 / 恢复"按钮

**有效时间**（仅当任一字段非空时展示）：
- 开始时间 ~ 结束时间
- 时间描述

#### 1.4.3 右侧 · 操作区

操作按钮按状态显示：

| 当前状态 | 编辑 | 通过 | 拒绝 | 撤回 | 删除 | 日志 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 🟡 待审核 | ✓ | ✓ | ✓ | — | ✓ | ✓ |
| 🔵 已审核 | ✓（仅改内容） | — | — | ✓（→待审核） | ✗ | ✓ |
| ⚪ 已拒绝 | ✗ | — | — | ✓（→待审核） | ✓ | ✓ |

**关键规则**：
- 已审核 / 已拒绝 状态确定后不可重复横跳；编辑只改内容、不改状态
- 已拒绝可撤回到待审核（缓冲池为临时区，允许反悔）
- 日志按钮带条数 Tooltip："查看操作记录（N 条）"

### 1.5 编辑抽屉（双栏）

打开方式：行内"编辑"按钮 → 右侧 60% 屏宽抽屉。

#### 1.5.1 左栏 · 事实内容

- 事实内容（必填，Textarea）
- **实时冲突 / 重复提示**（基于当前 content 调后端接口实时校验）：
  - 命中冲突：红框告警 + 冲突 ID Tag + 「查看对比」按钮
  - 命中重复：黄框告警 + 相似度 + 「查看对比」按钮
- **解除提示**：原本有冲突 / 重复，编辑后已不再命中 → 绿框「✓ 编辑后已不再与 [ID:xxx] 冲突，保存即生效」

#### 1.5.2 右栏 · 关联信息

- 关联实体（已存在）：搜索下拉添加，已选项可关闭
- 新发现实体（待入库）：
  - 卡片表单：实体名称（Input）/ 实体描述（Textarea）/ 标签（逗号分隔 Input）
  - 头部右上：丢弃 / 恢复 / × 删除
  - 底部「+ 添加新实体」按钮（手动补充 AI 漏抽的实体）
- 关联事件（已存在）：交互同实体
- 新发现事件（待入库）：
  - 卡片表单：事件名称 / 事件类型（Select：活动 / 赛事 / 版本更新 / 运营事件 / 其他）/ 开始时间 / 结束时间 / 时间描述 / 事件描述 / 标签
  - 头部右上：丢弃 / 恢复 / × 删除
  - 底部「+ 添加新事件」按钮
- 事实有效时间：开始时间 / 结束时间 / 时间描述

#### 1.5.3 保存逻辑

1. 触发"重新查冲突"：基于最新 content 调后端校验接口
2. 把校验结果（conflict / duplicate）写回审核区条目
3. 自动生成编辑摘要：`修改了：事实内容、关联实体、已解除与 [ID:42010] 的重复`，写入操作日志
4. Toast 提示"已保存"；若有冲突 / 重复解除，额外 toast"冲突已通过编辑解除"

#### 1.5.4 业务规则

- 抽屉首次打开（visible 从 false 变 true）才重置编辑态，避免编辑过程中被外部数据覆盖
- 已拒绝状态不允许打开编辑抽屉

### 1.6 冲突 / 重复对比 Dialog

打开方式：点击行内冲突 / 重复 Tag，或抽屉里「查看对比」。

**结构**：
1. **顶部详情区**（彩色背景）：
   - 冲突：⚠ Tag + 已有事实 ID + 冲突原因文字
   - 重复：≈ Tag + 已有事实 ID + 相似度（"86%"）
2. **中部双栏对比**：
   - 左：已有事实 [ID:xxx] 内容
   - 右：新事实内容
3. **底部差异高亮**：
   - 字符级或词级 diff（颗粒度由实现方决定）
   - 删除部分：红色删除线 + 红底
   - 新增部分：绿色 + 绿底
   - 头部图例提示

**业务规则**：
- diff 算法以可读为先
- Dialog 关闭只关闭，不影响事实数据

---

### 1.7 操作日志 Dialog

打开方式：行内"日志"按钮。

**结构**：
- 顶部：当前事实标题（前 30 字）
- 列表：每条日志一行
  - 动作 Tag（彩色，按 action 分色）
  - 详情文字
  - 操作人 · 时间

**记录的 action 枚举**：

| Action | 触发时机 |
|---|---|
| 创建 | AI 提取入审核区 |
| 编辑 | 抽屉保存（含字段 diff 摘要） |
| 通过 | 单条 / 整批通过 |
| 拒绝 | 单条 / 整批拒绝 |
| 撤回 | 已审核 / 已拒绝 撤回到待审核 |
| 实体丢弃 / 实体恢复 | 行内或抽屉里切换 keep / discard |
| 事件丢弃 / 事件恢复 | 同上 |
| 冲突解除 | 编辑保存后冲突不再命中 |
| 重复解除 | 编辑保存后重复不再命中 |

**业务规则**：
- 日志倒序展示（最新在最上）
- 日志只追加，不允许删除 / 修改

### 1.8 批量入库

入口：右上"已审核全部入库（N）"按钮。

**流程**：
1. 弹确认：「将{筛选范围} N 条已审核事实入库（直接以「已审核」状态进入事实库）。相关批次将自动归档到「已归档」区，可随时查看历史。」
2. 确认后：
   - 在事实库创建对应记录，初始状态 = "已审核"
   - 把所属批次置为已归档（archiveReason: committed）
   - 携带 source 信息（详见 §四 1 数据来源标记）
3. Toast "N 条事实已入库，相关批次已归档"

**业务规则**：
- 已审核 → 入库后**直接以「已审核」状态进入事实库**，不进行二次审核（审核区审核 = 唯一审核）
- 入库时所属批次自动归档（archiveReason: committed）到「已归档」区
- 范围切到"只看自己的"时，仅入库本人提取的"已审核"，不影响他人

### 1.9 待处理 / 已归档分区

审核区顶部加二级 Tab：

| Tab | 含义 | 包含批次 |
|---|---|---|
| 待处理 | 仍在工作流中的批次 | archived = false |
| 已归档 | 已完结的批次（导出 / 入库 / 手动归档） | archived = true |

**字段定义**：批次新增以下字段

| 字段 | 类型 | 说明 |
|---|---|---|
| archived | boolean | 是否已归档 |
| archiveReason | "exported" / "committed" / "manual" | 归档原因 |
| archivedAt | string | 归档时间 |
| archivedBy | string | 归档操作人 |
| exportedAt | string | 导出时间（archiveReason=exported 时记录） |

**自动归档触发**：
- 批量入库：选中条目所属批次 → archiveReason = committed
- 导出 Excel：选中条目所属批次 → archiveReason = exported
- **不支持手动归档**（已移除手动归档按钮，避免未完成审核的批次被误归档）

**取消归档**：
- 已归档区批次右上角"取消归档"按钮 → 恢复到待处理区
- 操作记录：写入"从已归档恢复为待处理"日志
- 不限制次数

**视觉**：
- Tab 显示数量徽章：`待处理 (N) · 已归档 (M)`
- 已归档批次头加状态 Tag：📎 已导出 / 📥 已入库 / 📁 已归档
- 已归档批次的事实行**只读**：编辑按钮变"查看"、隐藏多选 / 通过 / 拒绝 / 撤回 / 删除按钮

### 1.10 多选批量操作

每条事实左侧加多选 Checkbox（仅待处理区可见），勾选后页面顶部出现批量操作栏。

**多选状态**：
- 跨批次累加（Set<factId>）
- 切换 Tab / 提取人筛选时自动清空
- 选中后行背景轻微高亮（rgba(0,82,217,0.05)）

**批量操作栏内容**：
```
[全选框] 勾选条目或批次头进行批量操作；也可对单条点「通过/拒绝/撤回」
↓ 有选中时变为：
已选 N 条 · | 批量通过  批量拒绝  导出为 Excel  | 批量删除 | 清空选择
```

- 全选框常驻显示（未选中时带说明文字，选中后切换为操作按钮）
- 整批通过/拒绝/删除批次按钮：**有任意条目被多选时，所有批次的批量按钮统一隐藏**，避免视觉冗余与误操作；退出多选后自动恢复

**批量通过 / 批量拒绝**：
- 仅对选中条目中**状态为"待审核"**的生效；已标注的条目（已审核 / 已拒绝）静默跳过
- 操作日志写入："批量通过（多选）" / "批量拒绝（多选）"

**整批通过 / 整批拒绝（批次头按钮）**：
- 操作范围 = 该批次所有"待审核"条目（取差集，已标注的不动）
- Tooltip 解释："对当前批次所有「待审核」条目执行通过；已标注的条目不受影响"
- 待审核计数 = 0 时按钮自动隐藏，显示"归档"按钮代替

| 列名 | 内容 | 说明 |
|------|------|------|
| `id` | （空） | 留空，入库时系统分配 |
| `title` | （空） | 缓冲池无标题，导入后人工补充 |
| `content` | 事实内容 | |
| `category` | （空） | 导入后人工归类 |
| `sourceType` | （空） | |
| `source` | 提取人 | 便于溯源 |

| `relatedEvents` | 已有事件名称（逗号分隔） | |
| `conflictIds` | 冲突事实 ID | |
| `status` | `已审核` | 固定值 |

动态列（每条事实的新实体/事件按序号展开，decision ≠ discard 才输出）：

| 列名 | 内容 | 说明 |
|------|------|------|
| `new_entity_1` | 新实体名称 | |
| `new_entity_1_tmp_id` | `tmp_ent_xxx` | 提取时分配的临时 ID，跨字段引用用；后端聚合去重时替换为正式 ID |
| `new_entity_1_keep` | `1` | 默认 1；外部标注者可改为 0 表示不新增 |
| `new_entity_1_desc` | 实体描述 | 参考信息，不要求填写 |
| `new_entity_1_tags` | 实体标签（逗号分隔） | 参考信息 |
| `new_entity_2` … | 第 2 个新实体 | 按条目内新实体数量动态展开 |
| `new_event_1` | 新事件名称 | |
| `new_event_1_tmp_id` | `tmp_evt_xxx` | 同上 |
| `new_event_1_keep` | `1` | 同上 |

**关联实体/事件字段格式说明**：

`relatedEntities` / `relatedEvents` 字段使用 `id:name` 格式（多值逗号分隔），如：
```
123:维斯, 456:弧光玫瑰
```
- 已匹配实体（AI 提取阶段调 `entities/recall` 接口已定位到正式 ID）必须带 ID
- 未匹配的名称（兜底：导入时由后端按名称模糊匹配 / 进入新实体流程）输出为 `:名称`
- 真实环境下"已匹配实体"必带 ID，`:name` 仅作为 mock/兜底场景

**导入时后台处理逻辑**：

```
事实导入文件
  ↓
1. 状态过滤：仅 status=已审核 的行进入入库流程，其它跳过
  ↓
2. 关联实体/事件解析：
     - id:name 格式 → 按 ID 直接关联
     - :name（无 ID）→ 调 entities/recall 模糊匹配；命中则关联
     - 仍未命中 → 视为隐式新实体，进入新实体处理流程
  ↓
3. 新实体/事件去重聚合（核心步骤）：
     - 扫描所有 new_entity_* / new_event_* 列（_keep=1 的）
     - 跨批次/跨条目按"实体名称"聚合（不同 tmp_id 同名 → 合并为一个）
     - 检查实体库是否已存在同名实体（含别名匹配）
         - 已存在 → 复用现有 ID
         - 不存在 → 创建新实体，分配正式 ID
     - 维护 tmp_id → 正式 ID 的映射表
  ↓
4. 替换并入库：
     - 用映射表把事实的所有 tmp_id 引用替换为正式 ID
     - 事实入事实库，关联完整
     - tmp_id 丢弃（不入库）
  ↓
5. 反馈结果：
     - "创建了 N 个新实体，合并了 M 个重复建议，关联了 K 条事实"
```

**为什么需要 tmp_id**：

跨批次审核时，多个批次可能各自提出"提示音"作为新实体，如果不去重，每次入库都会创建一个独立的同名实体，污染实体库。tmp_id 让后端能区分"同一文件内不同位置引用同一个新实体"和"实际多个不同建议"，再按名称统一聚合。同样的逻辑同样适用于平台内单批次审批后入库——核心都是"入库时按名称聚合去重"。

**导出文件名**：`fact-export-YYYY-MM-DD.csv`（UTF-8 BOM）

**导出后行为**：
- 涉及批次自动归档 → archiveReason = exported
- 批次头展示：「📎 导出于 {时间} · 由 {操作人} 操作」

**外部标注者的职责边界**：
- 只负责事实内容审核（通过/修改/拒绝文本）
- `new_entity_*_keep` 字段：决定是否保留该新实体（1=保留 / 0=不增加）
- **不需要**填写实体 ID，平台在导入时自动处理

## 需求 2：多源批量导入【P0】

### 2.0 业务目标

支持业务方将白皮书、运营手册、Excel 表格等文件直接导入系统，自动解析为候选事实进入审核流，省去手工粘贴。

**入口**：

提取页（Extract Tab）顶部输入方式切换：
- 📝 文本粘贴
- 📎 文件导入

或独立按钮"批量导入"打开导入对话框。

---

### 2.1 文件解析

**支持文件类型**：

| 类型 | 扩展名 | 解析策略 |
|---|---|---|
| PDF | .pdf | 按章节 / 段落切分（每段 = 1 条候选事实） |
| Word | .docx | 同 PDF |
| Excel | .xlsx | 按行切分（每行 = 1 条候选事实，列名作为元数据） |
| CSV | .csv | 同 Excel |
| 纯文本 | .txt | 按段落切分（双换行符为段落边界） |

---

### 2.2 导入流程

1. 选择文件（单文件，首期不支持多文件）
2. 上传中：进度条 0~100%
3. 解析中：Loading + "正在解析文件结构…"
4. 解析完成 → 弹**预览 Dialog**：
   - 顶部：文件名 + 解析出的 N 条候选片段
   - 列表：每条片段（前 100 字预览 + 章节 / 行号标记）
   - 用户可勾选 / 取消勾选某条
   - 底部：模型选择 + 提取模式（同文本提取）
5. 点击"开始提取" → 后端针对每条勾选片段调 LLM
6. 提取完成 → 在右侧审核区**生成 1 个批次**：
   - extractor = 当前用户
   - sourceText = `来源文件：{文件名}\n\n【{片段位置}】\n{片段内容}\n\n…`（被提取的各片段位置+内容拼接）
   - batchLabel = `[白皮书] 文件名.pdf` 或 `[表格] 文件名.xlsx`
   - 批次头「查看原文」按钮在文件模式下文案改为「查看来源内容」，展开后展示 sourceText
   - mode = "文件解析"

---

### 2.3 业务规则

- 文件大小限制：PDF / Word ≤ 20MB，Excel / CSV ≤ 5MB（最终阈值由后端确定）
- 解析失败（如加密 PDF、损坏文件）→ 弹错误 Dialog 提示具体原因，不入审核区
- 表格类文件：列名应包含至少 1 个内容列（如"内容"/"问题"/"答案"），否则报错"未识别到内容列"
- 单次解析候选片段数 > 200 时，前端分页预览，后端可一次性处理
- 解析后直接进入审核流，与文本提取走同一入口，不引入额外审核步骤

---

### 2.4 导入对话框（实体 / 事件 / 事实）

实体 / 事件 / 事实管理页继续提供独立的"批量导入"对话框：
- 模板下载（CSV）
- 数据上传
- 导入记录 Tab：可回退、可中止

---

### 2.5 与其它模块的关联

- 解析得到的候选片段进入提取审核（需求 1）
- 入库后的事实，source 字段标明 `白皮书：xxx.pdf - 第3章` 或 `表格：xxx.xlsx - 第15行`，便于回溯

## 需求 5：操作记录与状态机校验【P0】

### 5.0 业务目标

每一次状态变更、字段编辑都可追溯；非法状态流转必须被阻止或明确告知用户。

---

### 5.1 状态机

**事实库（Fact）四态流转**：

```
待审核 ──通过──→ 已审核 ──发布──→ 已上线 ⇄ 已下线（重新上线）
   └── 拒绝 ──→ 不入库（被拒数据不留）
```

转移规则：

```
"待审核" → ["已审核"]
"已审核" → ["已上线"]
"已上线" → ["已下线"]
"已下线" → ["已上线"]
```

**实体 / 事件二态**：待审核 / 已审核（通过 = 转已审核）

**审核区条目三态**：待审核 / 已审核 / 已拒绝（详见 1.4.3）

---

### 5.2 批量操作的状态校验

批量审核 / 批量发布 时：
- 全部符合 → 直接执行
- 部分符合 → 弹确认 Dialog："选中的 N 条中：✅ M 条将变更，⚠ K 条已是目标状态，将跳过"
- 全部不符合 → toast 警告"所选记录均已是「目标状态」状态，无需变更"

---

### 5.3 操作记录字段

每个实体 / 事件 / 事实记录都有 `logs[]`：

| 字段 | 说明 |
|---|---|
| id | 自增 |
| operator | 操作人（登录态注入） |
| time | 操作时间 |
| action | 创建-手动 / 创建-导入 / 创建-提取 / 编辑 / 状态变更 / 同步 / 回退 / 删除 |
| detail | 详情文案（含字段 diff 摘要） |

**编辑日志的 detail**：自动 diff 字段差异，例如：

```
修改了：事实内容、关联实体（+「弧光玫瑰」）、有效时间（2026-04-23 → 2026-05-01）
```

---

### 5.4 操作记录入口

- 表格行操作列：「操作记录」按钮 → 弹 Dialog 展示该条记录的全量历史
- 跨记录的全局操作记录（批次导入 / 回退）：在批量导入对话框里有独立 Tab

---

### 5.5 与其它模块的关联

- 全模块复用同一套日志结构与展示组件
- 审核区阶段的日志独立（详见 1.7），入库后转换为事实库的日志（带 action="创建-提取"）

## 四、跨模块的关键约定

### 1. 数据来源标记

事实入库后必须有 source 类型标记，便于回溯：

| 来源类型 | source 示例 |
|---|---|
| AI 提取（文本） | `提取-文本：批次 BATCH-20260507-0001 · yzhinan` |
| AI 提取（白皮书） | `提取-白皮书：xxx.pdf - 第3章` |
| AI 提取（表格） | `提取-表格：xxx.xlsx - 第15行` |
| 批量导入（白皮书） | `白皮书：xxx.docx` |
| 手工新建 | `手工：用户名` |

### 2. 多人协作约定

- 提取结果团队级共享可见，通过"提取人筛选"切换查看范围
- 事实 / 实体 / 事件单一所有权但人人可编辑，编辑必须留痕
- 同时编辑同一条记录时，**后保存覆盖**（首期不做版本冲突检测）

### 3. ID 与命名规范

- 事实 ID：自增数字（5 位起）
- 实体 ID：自增数字（5 位起）
- 事件 ID：自增数字（5 位起）
- **批次 ID（batchId）**：`BATCH-{YYYYMMDD}-{当日 4 位序号}`，例如 `BATCH-20260507-0001`
  - 该编号在批次卡片头以独立 Tag 显著展示，点击可一键复制
  - 入库后的事实 source 字段需带上 batchId，便于回溯到批次原文
  - 此编号同时为后续"外部审核链路"预留——外部审核者凭批次编号识别批次、内部凭编号反查原文
- 审核区条目 ID：`f_{batchId}_{seq}`（不入库时不分配正式事实 ID）

## 五、关键 UX 与文案规范

### 1. Toast 文案

| 场景 | 文案 |
|---|---|
| 提取完成 | 提取完成（{batchId}），生成 N 条事实 |
| 整批通过 | 整批通过 |
| 整批拒绝 | 已拒绝该批次 N 条事实 |
| 编辑保存 | 已保存 |
| 冲突解除 | 冲突已通过编辑解除 |
| 重复解除 | 重复已通过编辑解除 |
| 批量入库 | N 条事实已入库 |
| 同步重试 | 已重新提交同步任务（事实 ID） |
| 状态部分跳过 | 已对 M 个执行，N 个已跳过 |

### 2. 颜色语义（与 TDesign 主题色对齐）

| 用途 | 颜色 |
|---|---|
| 成功 / 通过 / 已审核 | success（绿） |
| 待办 / 待审核 / 同步中 | warning（黄） |
| 错误 / 冲突 / 拒绝 / 同步失败 | danger（红） |
| 中性 / 占位 / 已下线 / 已拒绝 | default（灰） |
| 强调 / 操作 / 已上线 | brand（蓝） |

### 3. 关键空状态

| 场景 | 空状态文案 |
|---|---|
| 审核区空 | 暂无审核数据，请在左侧输入文本后提取 |
| 筛选后无数据 | 当前筛选下暂无数据，可切换为「全部」查看其他人的提取结果 |
| 操作记录空 | 暂无操作记录 |
| 新发现实体 / 事件空 | 未检测到新实体 / 未检测到新事件 |

## 七、附：核心实体 / 类型示意

> 仅作沟通参考，具体实现以后端契约为准。

```ts
// 事实
interface Fact {
  id: number;
  title: string;
  content: string;
  status: "待审核" | "已审核" | "已上线" | "已下线";
  category: string;
  keywords: string;       // 关联实体 "[id1] name1, [id2] name2"
  relatedEvents: string;  // 关联事件 "[id1] name1"
  source?: string;
  sourceType?: string;    // AI生成 / 人工审核 / 白皮书 / 表格
  sourceUrl?: string;
  sourceContent?: string;
  startTime?: string;
  endTime?: string;
  timeDesc?: string;
  conflict?: string;      // "[ID:xxx] xxx, [ID:yyy] yyy"
  duplicate?: string;
  syncStatus?: "success" | "failed" | "pending";
  syncError?: string;
  syncAt?: string;
  logs?: OperationLog[];
}

// 审核区批次（提取结果按批次组织）
interface ExtractBatch {
  batchId: string;          // BATCH-{YYYYMMDD}-{NNNN}
  extractor: string;        // 提取人
  extractedAt: string;
  sourceText: string;       // 来源文本（含文件解析的全文摘要）
  batchLabel: string;       // 批次标题（前 40 字 / 文件名）
  model: string;
  mode: "单段提取" | "多段提取" | "文件解析";
  facts: ExtractedFact[];
  expanded: boolean;
  // 归档相关
  archived: boolean;
  archiveReason?: "exported" | "committed" | "manual";
  archivedAt?: string;
  archivedBy?: string;
  exportedAt?: string;
}

// 审核区条目
interface ExtractedFact {
  factId: string;
  content: string;
  entities: string[];                 // 已有实体名称
  newEntities: NewEntitySuggestion[]; // 待入库新实体
  events: string[];
  newEvents: NewEventSuggestion[];
  conflict: ConflictRef | null;
  duplicate: DuplicateRef | null;
  startTime: string;
  endTime: string;
  timeDesc: string;
  status: "待审核" | "已审核" | "已拒绝";
  logs: BufferLog[];
}

interface NewEntitySuggestion {
  name: string;
  description: string;
  tags: string[];
  decision: "keep" | "discard";
}

interface NewEventSuggestion {
  name: string;
  eventType: string;
  startTime: string;
  endTime: string;
  timeDesc: string;
  description: string;
  tags: string[];
  decision: "keep" | "discard";
}

interface ConflictRef  { factId: string; factContent: string; reason: string; }
interface DuplicateRef { factId: string; factContent: string; similarity: number; }

interface BufferLog {
  id: number;
  time: string;
  operator: string;
  action: "创建" | "编辑" | "通过" | "拒绝" | "撤回"
        | "实体丢弃" | "实体恢复" | "事件丢弃" | "事件恢复"
        | "冲突解除" | "重复解除";
  detail: string;
}

interface OperationLog {
  id: number;
  operator: string;
  time: string;
  action: "创建-手动" | "创建-导入" | "创建-提取" | "编辑" | "状态变更" | "回退" | "同步" | "删除";
  detail: string;
}
```
