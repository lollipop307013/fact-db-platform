## 需求 7：错误表述检测【P1】

### 7.0 业务目标

批量修复库内错误表述——通过算法 + 模型对错误事实做检索 / 判断 / 修复，提升存量数据质量。

对应接口（三步法）：

1. `POST /api/facts/recall-error-expressions`
2. `POST /api/facts/check-error-expressions`
3. `POST /api/facts/correct-error-expressions`
4. `POST /api/facts/batch-update-corrected`（**写回入库**）

---

### 7.1 输入配置区

| 字段（接口参数） | 控件 | 必填 | 说明 |
|---|---|---|---|
| error_text | Input | ✓ | 错误表述文本 |
| correct_text | Input | ✓ | 正确表述文本 |
| original_content | Textarea | — | 完整原始内容（提供上下文） |
| recall_methods | Checkbox 多选 | — | 召回方式：模糊匹配 / 实体匹配 / RAG 召回（接口字段 `recall_methods[]`） |
| only_approved | Switch | — | 仅使用 review_status=approved 的事实（默认开） |
| parent_game_id | （隐藏） | ✓ | 顶部游戏切换 |

---

### 7.2 模型设置区

| 字段（接口参数） | 控件 | 说明 |
|---|---|---|
| extract_model_name | Select | 提取关键片段的模型（步骤 1） |
| filter_model_name | Select | 筛选过滤的模型（步骤 1） |
| model_name | Select | 判断 / 修复模型（步骤 2、3、4） |

---

### 7.3 处理操作区

#### 执行模式切换

| 模式 | 说明 | 接口 |
|---|---|---|
| **分步执行**（默认） | 步骤 1 检索 → 步骤 2 判断 → 步骤 3 修复 → 步骤 4 写回 | recall → check → correct → batch-update-corrected |
| **一步检测**（首期不做） | 一次完成判断与修复建议 | check-and-correct-error-expressions |

主按钮：「开始检测」

---

### 7.4 结果展示区

| 区块 | 数据来源 | 内容 |
|---|---|---|
| 统计信息 | 各步骤返回的统计 | 检索数量、命中数、修复数等 |
| 参考实体 / 事件 | check 接口返回的 entity_ids / event_ids | 从 original_content 提取的关联节点 |
| 检测结果列表 | check + correct 拼接 | 每行显示：fact_id / 原文 / 修正建议 / changes diff / 是否命中错误 |

#### 列表行操作

- 单条勾选 / 全选
- "隐藏无错误事实"快捷开关
- "清除结果"

---

### 7.5 批量更新入库 ⚠️ v2.0 补做

> 这是 v1.0 缺失的关键能力——检测出修复建议但无法写回。

#### 入口

检测结果列表底部按钮：「批量更新入库（已选 N 条）」

#### 流程

1. 用户勾选若干条要写回的修复结果
2. 点击按钮 → 弹确认 Dialog 列出将更新的 fact_id 列表
3. 调 `POST /api/facts/batch-update-corrected`：
   - error_text / correct_text / original_content 沿用本次检测的输入
   - updates[] = 选中条目的 { fact_id, fact_text }
4. 后端返回 updated_count 和 record_file（操作记录文件）
5. Toast："已写回 N 条修正"
6. 列表对应行显示"✅ 已入库"，且不可重复操作

---

### 7.6 业务规则

- 检测出的错误项仅给修复建议，**勾选后才落库**；防止误改
- 多次检测结果可叠加查看，或一键清除
- 写回操作落入操作记录（详见[子5](https://tapd.woa.com/tapd_fe/10153191/story/detail/1010153191134126267)）

---

### 7.7 与其它模块的关联

- 检测结果回写事实管理 Tab：写回成功的事实 fact_text 字段被更新
- 复用顶部全局游戏切换 / 语言切换
